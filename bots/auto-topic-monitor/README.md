# 汽车选题监控流程 SOP

> 改写自 GitHub 项目 [saas-growth-agents](https://github.com/Pluviobyte/saas-growth-agents) 的 **newterm（新词监控）** 与 **social-kb（内容归档）** 两条 SOP。
> 原版面向出海 SaaS 找搜索词；本文把它换成汽车行业每天找选题、拆爆款、存知识库的流程。
> 版本：2026-11-12 ｜ 适用：汽车品牌 / 经销商新媒体与用户增长团队

---

## 一、先回答：这到底是不是一个 Skill？

**整体不是。它是一个「给 AI Agent 用的岗位模板仓库」。**

可以把它想成一套「岗位说明书 + 工具箱 + 几张技能卡」：

| 仓库里的东西 | 作用 | 类比 |
|---|---|---|
| `AGENTS.md` | 安装总说明，Agent 读它后一步步把自己装成某个岗位 | 入职手册 |
| `bots/newterm/job.md` | 岗位说明：这个岗位每天干什么、怎么装、要哪些 Key | 岗位职责书 |
| `bots/newterm/routines.md` | 例程表：几点跑什么 | 排班表 |
| `bots/newterm/check.md` | 装好后的验收清单 | 上岗考核 |
| `bots/newterm/skills/*/SKILL.md` | 真正的「技能卡」：判断规则、门槛、播报格式 | 操作手册 |
| `bots/newterm/pipeline/*.py` | 干活的脚本：采集、去重、打分、生成报告 | 工具 |
| `bots/social-kb/` | 另一条岗位线：内容归档 | 另一个岗位 |

仓库里有 **5 个真正的 `SKILL.md` 技能文件**：

1. `newterm-monitor` —— 新词监控的完整打法（词源、门槛、播报格式）
2. `getting-started` —— 第一次安装时的一问一答引导
3. `directory-submit` —— 出海站点提交导航站
4. `douyin-comments` —— 抖音评论区抓取（独立技能）
5. `agent-setup` —— 帮用户生成安装话术的装机助手

**所以准确说法是：**
> 它是一套「Agent 岗位模板库」；里面每个具体能力用 Skill 的格式封装，但整个仓库不是一个可以直接丢进技能目录的 Skill。

**对我们的意义：**
- 值得学的是它的**流程骨架**：预跑与播报分离、一手源首见即报、二手源过门槛、去重台账、手机优先播报、失败必须明说。
- 不必照搬它的脚本：它的数据全走 AIsa 付费接口（一个 Key 调几千种 API，按次计费），汽车行业的大部分信息用免费网页 + 已登录浏览器就能拿到。
- 落地到 DSH 的正确姿势：把本文档压缩成一份 `SKILL.md`，再用定时任务跑，不需要安装整个仓库。

## 二、原版两条 SOP 拆解

### 2.1 newterm：新词监控

**核心流水线：**

```
          ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
 07:30    │  预跑采集     │ ──→  │  落盘成文件   │ ──→  │  播报只汇总   │  08:30
 采集窗口  │ 只采不发消息  │      │ report/radar │      │ 不重跑采集    │  发给人看
          └──────────────┘      └──────────────┘      └──────────────┘
                                      │
                                      ▼
                               ┌──────────────┐
                               │ pushed.json  │  推过的词记下来，下次不重复
                               └──────────────┘
```

**调度表（原版，Asia/Shanghai）：**

| 例程 | 时间 | 做什么 |
|---|---|---|
| 早间预跑 | 08:20 | 采集，只写文件，不发消息 |
| 早报 | 09:30 | 读预跑结果，写中文播报 |
| 午间预跑 | 10:20 | 同上，省掉贵的打分 |
| 午报 | 11:58 | **只报新词，没有就不说话** |
| 晚间预跑 | 16:20 | 同上 |
| 晚报 | 17:50 | 同早报 |
| 夜间采集 | 00:30、04:30 | 只补采，不播报 |

**四条关键规则（最值得抄）：**

1. **源分两类**
   - 一手源：首见即报，不看热度（社交平台新梗、竞品 sitemap 新页面、Product Hunt 新品、GitHub Trending）
   - 二手源：必须过热度门槛才报（策展词库、Trends 热搜，门槛 ≥ 基线 ×0.2）

2. **热度用「倍数」不用原始数字**
   - 统一写成 `GPTs × N` = 过去 7 天全球平均热度 ÷ GPTs 这个常青词的基线
   - 好处：不同词、不同时间、不同平台可以放在一张表里比较
   - 绝不直接甩 Trends 原始指数（那个数字没有可比性）

3. **去重靠台账**
   - `pushed.json` 记录所有推过的写法
   - 当天同写法不重复推；隔天仍过门槛可以标「再推」
   - 午报只报全新词或老话题的新写法

4. **失败必须明说**
   - 数据源报错或预跑超时，在播报开头写一行说明
   - **别把「没采到」当成「今天没有新词」**

**播报格式（手机优先）：**
- 开头最多两行：标题 + 一行计数，例如 `新增 23：新词 5 · 新写法 12 · TikTok早期 4`
- 不用表格；节与节之间空一行；每个词前空一行
- 每个词固定字段：热度、来源、是做什么的、竞品网站（可选）、风险（可选）
- 空节写「无」，不解释

**意图过滤（不是「没量」）：**
跳过常青教程、纯导航、体育赛程、季节性老词、品牌购物词、一日暴涨就崩的词、政治新闻。

### 2.2 social-kb：内容归档

**核心流水线：**

```
 你发一条链接
      │
      ▼
 ① 查重（收过就回「已经收过」）
      │
      ▼
 ② 取原文（按平台走对应接口；拿不到就如实说）
      │
      ▼
 ③ 结构化整理：一句话总结 / 核心要点 / 可操作步骤 / 工具链接 / 作者原链接 / 主题标签
      │
      ▼
 ④ 对照现有工作流：已在做 / 值得做 / 无关
      │
      ▼
 ⑤ 入库：kb/<主题>.md，同主题合并
      │
      ▼
 ⑥ 回复：一句话总结 + 值得做的建议
```

**知识库结构：**

```
工作目录/
├── inbox/            原始素材（JSON，保留原文）
└── kb/
    ├── AI 视频.md     一个主题一个文件，新条目追加
    ├── 出海SEO.md
    └── index.jsonl    一行一条：时间、主题、链接、标题（去重和周报都读它）
```

**周报：** 每周日 21:00，取最近 7 天新增，挑出最值得动手试的三条，说清为什么、第一步做什么；没有新增就回「本周无新增」。

**三条底线：**
- 只整理、不评论、不转发、不替人发帖
- 缺工具、缺数据、接口报错必须说，别跳过或编造
- 值得做的部分只给建议，由人确认后再改流程

## 三、汽车选题监控：整体设计

### 3.1 监控什么：五类线索

原版监控的是「新出现的搜索词」；汽车行业要监控的是「值得拍的新鲜事」。分成五类：

| 类型 | 具体来源 | 抓什么 | 进播报的条件 | 频率 |
|---|---|---|---|---|
| **① 新车/改款** | 工信部新车申报目录；品牌官网「新车/预售」页；汽车之家、懂车帝、易车的新车频道 | 新车名、申报图、配置、预售价、上市时间 | **首见即报**，不看热度 | 每日 |
| **② 竞品动作** | 竞品官网促销页；竞品门店抖音号/视频号；汽车之家降价频道 | 官降、限时权益、置换补贴、门店活动、新话术 | 官方发布首见即报；门店内容互动 ≥ 基线 ×2 | 每日 |
| **③ 政策/行业** | 工信部、商务部、财政部、税务总局；中汽协/乘联会销量数据；地方车管所 | 购置税、补贴、限牌、智驾法规、召回、销量榜 | **首见即报**，标注影响车型和地区 | 每日 |
| **④ 用户声音** | 车质网投诉榜；黑猫投诉；抖音/小红书评论区；车主论坛 | 高频抱怨、质量问题、服务槽点、购车疑问 | 同一问题 ≥3 条独立提及，或投诉量周环比 +50% | 每日/每周 |
| **⑤ 爆款内容** | 对标账号近 7 天新发；抖音热榜汽车话题；小红书汽车话题；企业号后台视频榜单 | 选题、开头钩子、结构、评论区反应 | 互动 ≥ 账号近 30 天中位数 ×2 | 每日 |

> 方法论依据（来自汽车新媒体课件）：
> - 选题 = **内容（用户诉求）+ 形式（自身价值呈现）**，不是单纯追热点。
> - 起步期最有效的两招是「蹭热点」和「复制」：找对标账号，从近期到往期筛优质选题进行复制；按视频类型搜关键词找参考。
> - 爆款选题可从企业号后台「数据分析 → 短视频 → 视频榜单 → 行业选汽车」找，翻拍符合自身定位的。
> - 出处课件：《短视频运营：推荐机制、内容定位与拍摄发布》《账号定位与审核要点》《汽车4S店AI素材制作实战》。

### 3.2 选题分级：A / B / C

| 级别 | 定义 | 处理方式 | 例子（示例） |
|---|---|---|---|
| **A 级** | 当天必须知道，直接影响销售话术 | 当天进选题会，24 小时内定 | 某车型官降 2 万；某地补贴新政；某品牌召回 |
| **B 级** | 值得跟，3 天内可拍 | 进选题池，3 天内排期 | 竞品门店做「交车仪式」爆款；某车型改款谍照 |
| **C 级** | 早期信号，先观察 | 进观察池，每周捞一次 | 某博主提到的新功能；评论区零散抱怨 |

**分级不看「感觉」，看两条：** ① 是否影响成交话术；② 是否有可拍素材（图/视频/实车）。

### 3.3 热度怎么算：基线倍数

原版用 `GPTs × N`，汽车版用 **「基线 × N」**：

```
热度 = 当前内容互动量 ÷ 同平台同类型内容近 30 天中位数
```

- 同平台：抖音只和抖音比，小红书只和小红书比，公众号只和公众号比
- 同类型：车型讲解和车型讲解比，剧情段子和剧情段子比
- 起步阈值建议：**A 级 ≥3×，B 级 ≥2×，C 级 ≥1.5×**
- 跑两周后按自己账号的实际数据校准，不要一开始就定死

**为什么不用播放量绝对值：** 10 万播放对一个大号是日常，对一个小号是爆款；用「比自己过去的中位数」才有意义。

**一手源例外：** 新车申报、官降、政策、召回这类「首见即报」，不看热度——因为它们本身就决定了你要不要改话术。

### 3.4 去重与选题台账

原版用 `pushed.json`；汽车版用 **两个文件**：

1. `pushed.json` —— 只记「推过的选题」，防止重复播报
2. `选题台账.csv` —— 记全生命周期，能看出每条选题从哪来、到哪去

**台账字段：**

| 字段 | 说明 | 示例 |
|---|---|---|
| 日期 | 发现日期 | 2026-11-12 |
| 选题 | 一句话标题 | 问界 M8 改款申报 |
| 类型 | 新车/竞品/政策/用户声音/爆款内容 | 新车 |
| 来源 | 具体来源 + 链接 | 工信部申报目录 |
| 热度 | 基线 ×N 或「首见」 | 首见 |
| 分级 | A/B/C | A |
| 状态 | 待评/已定/已拍/已发/搁置 | 已定 |
| 负责人 | 谁跟 | 张三（示例） |
| 计划发布 | 日期 | 11-14 |
| 实际发布 | 日期 | 11-15 |
| 数据回收 | 播放/点赞/线索 | 待回收 |

**去重规则：**
- 同一选题 7 天内不重复推
- 同一选题有了实质进展（申报 → 预售 → 上市 → 交付）可以「再推」，标明阶段
- 午报只报上午新增，不重复早报

### 3.5 每天怎么跑（时间表）

按汽车门店/内容团队作息设计，可按实际调整：

| 时间 | 例程 | 做什么 | 是否打扰人 |
|---|---|---|---|
| 07:30 | 预跑 | 采集五类线索，写进当天文件夹 | 否 |
| 08:30 | **早报** | 读预跑结果，发 A/B 级选题；选题会前看 | 是 |
| 12:30 | 午报 | 只报上午新增；没有就不发 | 是（可静音） |
| 17:00 | 晚报 | 汇总当天全部，定次日选题 | 是 |
| 周日 20:00 | 周报 | 本周选题复盘 + 爆款内容归档 + 下周预判 | 是 |

**关键：预跑和播报分开。** 重采集放在不打扰人的时间，播报只做「读文件 + 写人话」，快且稳。

### 3.6 播报模板（手机版）

```
【汽车选题雷达｜11月12日 早报】
新增 5：新车 1 · 竞品 2 · 政策 1 · 用户声音 1

一、新车/改款

**1. 问界 M8 改款（示例）**

- 热度：首见
- 来源：工信部申报 · 11/10
- 是什么：中大型 SUV 改款，主要变化在前脸和智驾硬件。
- 为什么现在拍：申报图已出，用户开始搜「改款长什么样」。
- 可拍角度：① 申报图对比老款 ② 改款值不值得等 ③ 老车主怎么看
- 风险：官方未公布价格，别把推测说成确定。
- 链接：<来源链接>

二、竞品动作

**2. 某品牌深圳门店「交车仪式」视频（示例）**

- 热度：基线 ×2.4
- 来源：抖音 · 对标账号 · 11/11
- 是什么：单条交车视频，点赞 1.2 万，评论区大量问价格。
- 为什么现在拍：同城同价位，形式可复制。
- 可拍角度：① 同款仪式 ② 客户真实反应 ③ 交付流程科普
- 风险：别拍成硬广，重点是客户体验。

三、政策/行业

无

四、用户声音

**3. 某车型车机卡顿集中反馈（示例）**

- 热度：基线 ×1.8
- 来源：车质网 + 抖音评论 · 11/09-11/11
- 是什么：三天内 7 条独立提及，集中在早高峰启动慢。
- 可拍角度：① 实测 ② 官方优化进度 ③ 老车主应对办法
- 风险：别替品牌下结论，先求证。
```

**格式规则（照抄原版）：**
- 不用表格
- 节与节之间空一行
- 每个选题前空一行
- 空节写「无」
- 开头最多两行，省略批次号和方法论文

### 3.7 人工审批点（必须保留）

| 节点 | 谁决定 | AI 能做什么 |
|---|---|---|
| 选题定稿 | 内容负责人 | 给候选、给理由、给风险 |
| 拍摄脚本 | 编导/店长 | 出初稿、给参考 |
| 发布 | 账号负责人 | 排期提醒、文案校对 |
| 投放预算 | 市场负责人 | 给历史数据参考 |
| 删除/下架 | 品牌负责人 | 提醒风险，不自动操作 |

**AI 只做「发现、整理、起草」，不做「拍板、发布、花钱」。**

## 四、内容归档：汽车版

### 4.1 归档什么

- 刷到的对标爆款视频/笔记（抖音、小红书、视频号）
- 竞品好的直播话术、活动海报、交车仪式
- 行业好文章、政策解读
- 自己团队发过的内容（用于复盘）

### 4.2 六步流程（照搬 social-kb）

1. **查重**：这条链接收过没有？收过直接回「已经收过」+ 当时主题
2. **取原文**：
   - 抖音：用 `douyin-comments` 技能取标题、简介、评论区；视频无字幕就如实说明只拿到简介
   - 小红书：用 `xhs-notes` 技能（需 USB 连接已登录手机）
   - 公众号/网页：用网页抓取
   - 拿不到就直说，**不根据标题编总结**
3. **结构化拆解**（见 4.3）
4. **对照现有工作流**：哪些已在做 / 哪些没做但值得做 / 哪些无关；值得做的只给建议，人确认后再改
5. **入库**：写进 `kb/<主题>.md`，同主题合并，不重复
6. **回复**：一句话总结 + 值得做的建议（不贴全文）

### 4.3 拆解模板：脚本七要素 + 选题公式

来自汽车新媒体课件的「脚本拆解七要素」：

| 维度 | 要回答的问题 |
|---|---|
| **1. 视频类型** | 原产地型 / 用户场景型 / 剧情型 / 仓库型 / 人设型 / 种草型 / 展款型？ |
| **2. 开头爆点** | 前 3–5 秒靠什么抓人：冲突、痛点、情绪、效果展示、反转？ |
| **3. 中间产品阐述** | 怎么组织：产品展示、人设、材质、外观、功能演示、场景、痛点解决、价格？ |
| **4. 末尾转化设计** | 怎么引导：优惠力度、保障、稀缺感、到店邀请？ |
| **5. 人物风格** | 专家 / 素人 / 销售 / 车主 / 剧情角色？ |
| **6. 配音配乐** | 音乐情绪和作用；有没有用热门 BGM？ |
| **7. 环境布局** | 门店、车间、户外、车内、家里？场景如何服务信任感？ |

再加一条**选题公式**：

```
选题 = 内容（用户诉求）+ 形式（自身价值呈现）
```

- 用户诉求：价格、配置、续航、智驾、空间、售后、面子、省钱

### 5.2 三步走：先手动，再半自动，最后全自动

**第 1 周：手动跑（纯人工，先别设定时）**
- 每天你自己发 3–5 条链接给 AI，让它按 4.2 整理
- 每天人工填一次选题台账
- 目的：验证播报格式和拆解模板是否顺手，改到满意

**第 2 周：半自动**
- 建「早报」定时任务：AI 按 3.1 采集五类线索，按 3.6 出草稿
- 你审核后转发到工作群
- 内容归档仍然手动发链接

**第 3 周：全自动**
- 加午报、晚报、周报
- 加竞品账号固定监控
- 用前两周台账校准热度门槛
- 敏感动作（发布、投放、删除）继续人工审批

## 六、验收清单（照原版 check.md 改）

1. 早报能在 08:30 前发出，五类线索都有覆盖（没有的写「无」）
2. 每条选题有：热度、来源、是什么、可拍角度、风险
3. 同一选题 7 天内不重复推；升级阶段标「再推」
4. 数据源失败时，播报开头有说明，没把「没采到」写成「今天没有」
5. 台账能导出，能看到每条选题的来源、分级、状态、负责人、发布数据
6. 内容归档：同一链接第二次发，能回「已经收过」
7. 内容归档：拿不到正文时，明确说原因，不编总结
8. 周报每周日 20:00 出，能挑出 3 条可执行建议
9. 所有对外发布、投放、删除动作都经人确认

## 七、边界与注意

- **不自动发布、不自动投放、不替人做选题决定。** AI 是情报员和助理，不是主编。
- **平台抓取要克制。** 抖音评论、小红书笔记都用你自己已登录的账号环境；出现验证码就停下叫人，不代点。
- **引用他人内容只做学习记录，不搬运发布。**
- **传闻必须标注「未证实」。** 新车谍照、配置猜测、价格爆料，来源和可信度要写清楚。
- **数据带日期。** 销量、投诉量、互动量都写清统计周期，避免拿旧数据当现在。
- **付费接口先问价。** 原版每次请求都带最高价，超价直接拦下；我们如果用 AIsa，也先 `--quote` 问价再跑。
- **不要照搬原版的所有词源。** 原版盯的是 AI 工具站和搜索词；汽车行业盯的是车、价、政策、人，词源表要按你的品牌和价位带重写。
